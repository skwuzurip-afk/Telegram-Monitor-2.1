TELEGRAM MONITOR 2.0
Отслеживание доступных изменений Telegram-профиля
================================================================

Windows 10/11 + Python + обычное окно CMD.
Без графического интерфейса, без ASCII-рисунков, без очистки экрана.
Программа фиксирует только те данные, которые Telegram разрешает
видеть вашему аккаунту. Настройки приватности не обходятся.


----------------------------------------------------------------
1. ЧТО ДЕЛАЕТ ПРОГРАММА
----------------------------------------------------------------

Фиксирует в журнале с датой и временем:

  - STATUS: ONLINE          цель появилась в сети (если статус виден);
  - STATUS: OFFLINE         цель вышла из сети;
  - LAST SEEN CHANGED       изменилось доступное время последнего визита;
  - STATUS: HIDDEN          Telegram показывает только приблизительное
                            «недавно / на прошлой неделе / в прошлом месяце»;
  - STATUS: UNAVAILABLE     статус вообще не отдаётся вашему аккаунту;
  - FIRST NAME CHANGED      изменено имя (OLD и NEW);
  - LAST NAME CHANGED       изменена фамилия (OLD и NEW);
  - USERNAME CHANGED        изменён username (OLD и NEW);
  - BIO CHANGED             изменено описание профиля (OLD и NEW);
  - PROFILE PHOTO CHANGED   изменена аватарка (OLD и NEW файлы);
  - PROFILE PHOTO REMOVED   аватарка удалена;
  - TARGET CHANGED          username стал указывать на другого пользователя.

Для видимой онлайн-сессии сохраняется её длительность.
Аватарки складываются в DATA/avatars/ и не удаляются автоматически.
Все события хранятся в SQLite и переживают закрытие CMD и перезагрузку ПК.

    avatar_tracker.py - архив фотографий, photo_id, имена файлов;

    requirements.txt  - зависимость Telethon.

    settings.json     - настройки (api_id, api_hash, телефон, цель, флаги);

    avatars/           - архив аватарок (avatar_001.jpg, avatar_002.jpg...);

  LOGS/
    monitor.log       - служебный журнал и ошибки (ротация до 3 файлов по 2 МБ).

3. ТРЕБОВАНИЯ
----------------------------------------------------------------

  - Windows 10 или 11;
  - Python 3.10 или новее (проверено на 3.12);
  - интернет;
  - ваш аккаунт Telegram;
  - api_id и api_hash вашего приложения Telegram (бесплатно).


----------------------------------------------------------------
4. УСТАНОВКА
----------------------------------------------------------------

1) Распакуйте ZIP в локальную папку, например:

       C:\TelegramMonitor

   Не запускайте программу из OneDrive/облачной папки: синхронизация
   может блокировать файл базы. Если проект уже лежит в OneDrive,
   скопируйте папку в C:\TelegramMonitor.

2) Установите Python, если его нет:

       https://www.python.org/downloads/windows/

   При установке обязательно отметьте:
       Add python.exe to PATH

3) Запустите CONFIG.bat или START.bat.
   При первом запуске программа сама установит Telethon
   (нужен интернет). Отдельный установщик не требуется.

   Если автоматическая установка не сработала, откройте CMD:

       cd /d C:\TelegramMonitor
       python -m pip install -r LIB\requirements.txt


----------------------------------------------------------------
5. ГДЕ ВЗЯТЬ api_id И api_hash
----------------------------------------------------------------

1) Откройте https://my.telegram.org и войдите под своим номером.
2) Откройте «API development tools» и создайте приложение
   (название и платформа любые, например Monitor / Desktop).
3) Скопируйте api_id (число) и api_hash (32 символа).
4) Введите их в CONFIG.bat, пункты 1 и 2.

api_id/api_hash — ключи вашего приложения Telegram.
Не передавайте их посторонним и не публикуйте.


----------------------------------------------------------------
6. ПЕРВЫЙ ЗАПУСК И АВТОРИЗАЦИЯ
----------------------------------------------------------------

Порядок:

1) Запустите CONFIG.bat.
2) Заполните пункты 1-5:
   - API ID;
   - API HASH;
   - номер телефона в формате +79991234567;
   - username цели (например @durov);
   - интервал проверки.
   Настройки сохраняются сразу после каждого изменения.
3) Закройте CONFIG.bat (пункт 0).
4) Запустите START.bat.

При первом запуске START.bat:
   - подключается к Telegram;
   - отправляет код подтверждения в приложение Telegram;
   - просит ввести код в окно CMD;
   - если включена двухэтапная проверка — просит пароль;
   - сохраняет сессию в DATA/sessions/account.session;
   - печатает информационную панель и начинает мониторинг.

Код и пароль не сохраняются. Сама сессия сохраняется, поэтому
при следующих запусках код обычно не нужен.

Если настройки не заполнены, START.bat сам запустит пошаговый
мастер первичной настройки.

Важно: вход выполняется под ВАШИМ аккаунтом. Программа видит только
то, что Telegram показывает этому аккаунту.


----------------------------------------------------------------
7. CONFIG.BAT — МЕНЮ НАСТРОЕК
----------------------------------------------------------------

  1  - Telegram API ID
  2  - Telegram API HASH (при просмотре маскируется)
  3  - Номер телефона (при просмотре маскируется)
  4  - Username отслеживаемого аккаунта
  5  - Интервал проверки
  6  - Отслеживание статуса .............. ON/OFF
  7  - Отслеживание изменений профиля .... ON/OFF
  8  - История аватарок .................. ON/OFF
  9  - Сохранение истории в базу ......... ON/OFF
  10 - Вывод событий в CMD ............... ON/OFF
  11 - Автозапуск Windows ................ ВКЛЮЧЁН/выключен
  12 - Просмотр текущих настроек
  13 - История / поиск / статистика / экспорт / резервная копия
  0  - Выход

Все настройки хранятся в DATA/settings.json и не сбрасываются
после перезапуска.

Если мониторинг уже запущен, изменения настроек (интервал, цель,
переключатели) применяются после остановки START.bat (Ctrl+C)
и нового запуска. Просмотр истории и экспорт можно делать
и во время мониторинга.

Что означают переключатели:

  - TRACK STATUS OFF: события статуса не пишутся, онлайн-сессии
    не учитываются. Изменения профиля продолжают работать.

  - TRACK PROFILE OFF: изменения имени, фамилии, username и bio
    не фиксируются. Архив аватарок при этом тоже не ведётся.

  - AVATAR HISTORY OFF: смена фотографии определяется, но файлы
    не скачиваются; в событии будет photo_id вместо имени файла.

  - SAVE HISTORY OFF: события показываются в CMD, но не пишутся
    в базу. История и статистика пополняться не будут.

  - PRINT EVENTS OFF: события не выводятся в CMD, но сохраняются
    в базу и в LOGS/monitor.log.

При просмотре настроек API HASH и телефон показываются частично.
Полные значения хранятся только в DATA/settings.json.


----------------------------------------------------------------
8. START.BAT — МОНИТОРИНГ
----------------------------------------------------------------

START.bat проверяет Python и Telethon, открывает базу, подключается
к Telegram и печатает панель:

====================================================
              TELEGRAM MONITOR
====================================================

PHONE:       +7********67
USERNAME:    @durov
STATUS:      ONLINE
INTERVAL:    60 sec
STARTED:     03.11.2026 07:30:12
====================================================

Ниже идёт непрерывный журнал. Экран не очищается.

Внизу окна постоянно видна одна служебная строка состояния. Она
обновляется на месте (через возврат каретки), новых строк при этом
не добавляется. Поэтому даже когда событий нет, видно, что программа
работает, когда была последняя проверка и какой сейчас статус:

  [07:30:12] CHECK OK | STATUS: ONLINE | VISIBLE: 12m 05s | NEXT 60s
  [07:42:08] CHECK OK | STATUS: OFFLINE | LAST SEEN: 07:42:05 | NEXT 60s
  [07:45:08] CHECK OK | STATUS: HIDDEN (RECENTLY) | NEXT 60s
  [07:46:08] CHECK FAILED | NO CONNECTION | RETRY 60s

Пояснения к нижней строке:

  CHECK OK         - проверка выполнена;
  CHECK FAILED     - связи нет или цель не найдена; будет повтор;
  STATUS           - текущее состояние цели;
  VISIBLE          - сколько длится видимая онлайн-сессия;
  LAST SEEN        - время последнего визита, если Telegram его отдаёт;
  HIDDEN           - точное время скрыто, показана приблизительная метка;
  NEXT / RETRY     - через сколько секунд будет следующая проверка.

Строка не пишется в LOGS/monitor.log и не считается событием.
Если вывод перенаправлен в файл или CMD не поддерживает обновление
строки, служебная строка автоматически отключается.

Примеры событий:

[07:30:12] STATUS: ONLINE
[07:42:08] STATUS: OFFLINE
    LAST SEEN: 03.11.2026 07:42:05
    VISIBLE SESSION: 11m 56s

[07:50:21] USERNAME CHANGED
    OLD: @old_name
    NEW: @new_name

[08:15:32] PROFILE PHOTO CHANGED
    OLD: avatar_001.jpg
    NEW: avatar_002.jpg

Остановка — Ctrl+C. Настройки и уже записанная история сохраняются.

Окно CMD должно оставаться открытым. При закрытии окна мониторинг
прекращается. Для работы 24/7 включите автозапуск и настройте
электропитание Windows так, чтобы компьютер не уходил в сон.


----------------------------------------------------------------
9. КАК ИЗМЕНИТЬ ИНТЕРВАЛ
----------------------------------------------------------------

Интервал не «зашит» в код. Он хранится в DATA/settings.json.

Через меню:
    CONFIG.bat -> пункт 5 -> введите число секунд.

Правила:
  - допустимый диапазон: 10-86400 секунд (24 часа);
  - рекомендуется 60 секунд или больше;
  - слишком частые запросы повышают риск FloodWait;
  - текущий интервал виден в CONFIG.bat и в панели START.bat;
  - изменение применяется при следующем запуске START.bat
    (остановите мониторинг Ctrl+C, измените, запустите снова).

Telegram может ограничить частоту запросов. Программа уважает
FloodWait и делает паузу на указанное сервером время.


----------------------------------------------------------------
10. АВТОЗАПУСК ПРИ ВХОДЕ В WINDOWS
----------------------------------------------------------------

Включение:
    CONFIG.bat -> 11 -> 1

Что происходит:
  - в реестр текущего пользователя добавляется запись
    HKCU\Software\Microsoft\Windows\CurrentVersion\Run
    с именем TelegramMonitor;
  - при следующем входе в Windows автоматически запускается
    START.bat и открывается окно мониторинга;
  - права администратора не нужны.

Отключение:
    CONFIG.bat -> 11 -> 2

Проверить вручную:
    reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v TelegramMonitor

Удалить вручную:
    reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v TelegramMonitor /f

Если папка проекта была перемещена или переименована, отключите
и снова включите автозапуск: запись в реестре хранит старый путь.

Второй экземпляр мониторинга не запускается: используется
DATA/monitor.lock. Это защищает от лишних запросов и дублей.


----------------------------------------------------------------
11. ИСТОРИЯ, ПОИСК, СТАТИСТИКА, ЭКСПОРТ, КОПИИ
----------------------------------------------------------------

Всё находится в CONFIG.bat -> пункт 13:

  1 - просмотр истории (постранично, новые сверху);
  2 - поиск по тексту, типу события и датам (ДД.ММ.ГГГГ);
  3 - статистика за сегодня и за 7 дней:
      ONLINE/OFFLINE, изменения LAST SEEN, скрытый статус,
      суммарное видимое время онлайн, изменения профиля,
      последнее известное посещение;
  4 - архив аватарок (имя файла, photo_id, дата, наличие файла);
  5 - экспорт всего журнала в TXT;
  6 - экспорт всего журнала в CSV (разделитель «;», UTF-8 BOM —
      открывается в Excel и Блокноте);
  7 - резервная копия базы (DATA/backups/history_backup_...db).

Экспорт сохраняется в DATA/exports/.


----------------------------------------------------------------
12. БАЗА ДАННЫХ И ФАЙЛЫ
----------------------------------------------------------------

DATA/history.db — SQLite. Таблицы:

  events    — все события: дата/время, тип, старое значение,
              новое значение, длительность сессии в секундах;
  sessions  — завершённые видимые онлайн-сессии;
  photos    — архив аватарок: дата, photo_id, имя файла;
  app_state — последнее состояние цели для защиты от дублей;
  meta      — версия схемы.

При каждом запуске выполняется быстрая проверка целостности
(PRAGMA quick_check). Если файл повреждён, он сохраняется рядом
как history.corrupt_ГГГГММДД_ЧЧММСС.db, а работа продолжается
с новой базой. Старую копию при необходимости можно восстановить
вручную.

Каждое событие и новое состояние цели записываются одной
транзакцией: внезапное закрытие окна не теряет уже записанное
и не создаёт дубли при следующем запуске.

Чтобы перенести историю на другой компьютер, скопируйте всю папку
проекта вместе с DATA/ (но не передавайте её посторонним).


----------------------------------------------------------------
13. БЕЗОПАСНОСТЬ
----------------------------------------------------------------

  - DATA/settings.json содержит api_id, api_hash и номер телефона.
  - DATA/sessions/account.session позволяет войти в ваш Telegram
    без кода подтверждения.
  - Никому не передавайте папку DATA и не публикуйте её в Git.
    Файл .gitignore уже исключает DATA/, LOGS/, *.session.
  - Программа не отправляет сессию и ключи никуда, кроме серверов
    Telegram, необходимых для работы официального API.
  - Пароль Telegram и код подтверждения не сохраняются.
  - Если сессия могла попасть к посторонним: в Telegram откройте
    «Настройки -> Устройства», завершите незнакомые сеансы,
    удалите DATA/sessions/account.session и войдите заново.
  - Используйте программу ответственно: отслеживайте только те
    профили, на которые у вас есть согласие и право.


----------------------------------------------------------------
14. ЧЕСТНЫЕ ОГРАНИЧЕНИЯ TELEGRAM
----------------------------------------------------------------

Это важно. Программа не обходит приватность и не выдумывает данные.

1) Статус может быть скрыт.
   Если человек скрыл «Время последнего посещения», точные
   ONLINE/OFFLINE недоступны. Программа покажет STATUS: HIDDEN
   или STATUS: UNAVAILABLE, а не ложный ONLINE.

2) Приблизительные статусы не считаются точным временем.
   «Недавно», «на прошлой неделе», «в прошлом месяце» — это
   приблизительные метки Telegram. Они показываются как HIDDEN
   и не превращаются в конкретные дату и время.

3) Telegram не присылает поток событий.
   Программа периодически опрашивает профиль. Если человек зашёл
   и вышел между проверками, ONLINE может быть не замечен.
   В таком случае фиксируется изменение LAST SEEN, если оно доступно.

4) Длительность сессии — это видимое программе время.
   Если компьютер был выключен, спал или программа не работала,
   часть сессии не видна. Для точного учёта ПК должен работать,
   а мониторинг — быть запущенным.

5) Старые аватарки доступны только если программа их видела.
   Предыдущая версия сохраняется, когда программа замечает смену.
   Фотографии, сменённые при выключенной программе, восстановить
   нельзя: Telegram не хранит для вас всю историю аватарок.

6) Смена username.
   Программа запоминает user_id цели и при следующем запуске
   продолжает следить именно за этим пользователем, даже если
   username изменился (событие USERNAME CHANGED). Поэтому если
   старый username занял другой человек, слежка не переключится
   на него автоматически. Чтобы перейти на другого пользователя,
   укажите его username или числовой ID в CONFIG.bat (пункт 4);
   состояние отслеживания будет сброшено.
   Если прежний user_id больше недоступен (аккаунт удалён,
   вы заблокированы, сессия его не помнит), программа попробует
   найти цель по username из настроек. Если этот username теперь
   принадлежит другому человеку, появится TARGET CHANGED
   и состояние сбросится.
   Чтобы принудительно начать заново с тем же username, введите
   его в CONFIG.bat (пункт 4) и подтвердите сброс состояния.
   Перед сменой цели остановите мониторинг (Ctrl+C): работающая
   копия хранит состояние в памяти до перезапуска.

7) Телефон как цель.
   Поиск по номеру работает только если Telegram разрешает вашему
   аккаунту его найти (например, номер есть в контактах).
   Основной способ — username или числовой ID.

8) Переписка, звонки, удалённые сообщения и другие приватные
   действия не отслеживаются. Через официальный API вашего
   аккаунта их получить нельзя.

9) Если человек хочет добровольно передавать свой статус,
   это возможно только отдельным решением на его стороне
   (например, собственный клиент/бот с его согласия).
   Данная программа работает только с публично доступными
   вашему аккаунту данными и ничего не обходит.


----------------------------------------------------------------
15. НАДЁЖНОСТЬ И ПОВЕДЕНИЕ ПРИ СБОЯХ
----------------------------------------------------------------

  - Пропал интернет: сообщение «No connection to Telegram. Retrying...»,
    повторные попытки с паузой, восстановление соединения.
    Нижняя строка при этом показывает CHECK FAILED и время повтора.
  - FloodWait: пауза ровно на время, указанное Telegram.
  - Нижняя строка состояния обновляется один раз за проверку и всегда
    показывает время проверки, статус и время следующего опроса.
    Если ничего не изменилось, новых строк в журнале не появляется.
  - Ошибки и служебные сообщения пишутся в LOGS/monitor.log.
    Нижняя строка состояния в журнал не пишется.
  - Событие и состояние цели сохраняются одной транзакцией.
  - Состояние цели в базе защищает от повторной записи тех же
    событий после перезапуска.
  - Незавершённая сессия: если программа была выключена недолго,
    сессия продолжается; если долго — закрывается по времени
    последней успешной проверки.
  - Второй экземпляр блокируется файлом DATA/monitor.lock.
  - Ctrl+C — корректная остановка, история сохраняется.
  - При повреждении базы она откладывается, создаётся новая.
  - После перезагрузки Windows мониторинг продолжается с той же
    базой (при включённом автозапуске — автоматически).


----------------------------------------------------------------
16. УСТРАНЕНИЕ НЕПОЛАДОК
----------------------------------------------------------------

«Python was not found»
   Установите Python с галочкой «Add python.exe to PATH»
   или добавьте папку Python в PATH.

«Installing required libraries...» и ошибка
   Проверьте интернет. Затем вручную:
       python -m pip install -r LIB\requirements.txt

«Target @... not found»
   Проверьте username в CONFIG.bat -> 4. Некоторые пользователи
   скрыты от поиска по username — тогда нужен числовой ID
   или номер из контактов.

«STATUS: HIDDEN» / «STATUS: UNAVAILABLE»
   Человек скрыл статус. Это ограничение Telegram, обойти нельзя.

«Telegram FloodWait: pause N sec.»
   Нормальная защита Telegram. Увеличьте интервал
   (CONFIG.bat -> 5), рекомендуется 60 секунд и больше.

Просит код при каждом запуске
   Проверьте, что папка DATA/sessions доступна для записи и файл
   account.session не удаляется. После смены пароля или завершения
   сеансов в Telegram вход потребуется заново.

«Telegram session is invalid»
   Вы вышли из аккаунта на другом устройстве. Удалите
   DATA/sessions/account.session и запустите START.bat заново.
   История в DATA/history.db сохранится.

Ошибка SQLite / база не открывается
   Закройте все копии программы. Повреждённая база будет отложена
   автоматически; резервные копии лежат в DATA/backups/.
   Не работайте с базой одновременно из OneDrive.

Окно закрывается сразу
   Запускайте START.bat. При ошибке окно останется с сообщением
   и предложением нажать клавишу. Подробности — LOGS/monitor.log.

Шрифт/цвет консоли
   По умолчанию CMD: белый текст на чёрном фоне.
   Правый клик по заголовку окна -> Свойства -> Шрифт
   (например, Consolas или Lucida Console).

17. ПРОВЕРКА ПРОЕКТА
----------------------------------------------------------------

Что проверено автоматически в этой сборке:

  - компиляция всех модулей LIB;
  - статическая проверка кода (pyflakes);
  - сохранение и повторная загрузка DATA/settings.json;
  - проверка интервала и нормализация username/ссылки;
  - маскирование api_hash и телефона при просмотре настроек;
  - создание схемы SQLite, целостность, резервное копирование;
  - восстановление после повреждённого файла базы;
  - события ONLINE/OFFLINE, LAST SEEN, HIDDEN, UNAVAILABLE;
  - длительность видимой онлайн-сессии;
  - отсутствие дублей при неизменных данных;
  - нижняя строка состояния: обновление на месте без новых строк,
    время проверки, ONLINE/OFFLINE/HIDDEN, длительность сессии,
    сообщение CHECK FAILED при сбое связи;
  - изменения имени, фамилии, username, bio со старыми и новыми
    значениями;
  - архив аватарок: avatar_001.jpg, avatar_002.jpg, photo_id, дата,
    отсутствие повторного скачивания той же версии;
  - статистика за день/неделю;
  - экспорт TXT и CSV;
  - защита от второго экземпляра;
  - полный цикл START с имитацией Telegram-клиента: панель,
    события, отсутствие дублей после перезапуска, смена цели;
  - запуск CONFIG.bat и отображение меню/настроек;
  - включение и отключение автозапуска (тестовая запись реестра
    создавалась и удалялась).

Что нельзя проверить без вашего аккаунта:

  - реальная отправка кода Telegram и вход с паролем 2FA;
  - фактические ответы Telegram по вашему конкретному профилю;
  - видимость статуса и аватарки именно для вашего аккаунта.

Эти вещи зависят от вашего номера, аккаунта и настроек приватности
цели. Программа не выдаёт их за проверенные: при недоступности
данных она честно пишет HIDDEN/UNAVAILABLE.

----------------------------------------------------------------
20. НОВОЕ В ВЕРСИИ 2.1
----------------------------------------------------------------

ИСПРАВЛЕНО: зависание на "CONNECTING" и предупреждение
"coroutine 'TelegramBaseClient.connect' was never awaited".
Причина: не был включён синхронный режим Telethon. Теперь в
LIB/telegram_client.py стоит "from telethon import sync".

РАМКА В CMD. Вместо одной строки состояния внизу окна рисуется
рамка: телефон, username, имя, статус, ID, число событий и аватарок,
описание, время проверки, обратный отсчёт, состояние модулей.
Обновляется на месте раз в секунду, события печатаются выше неё.
Если у вас не отображаются линии, включите ui_ascii в settings.json
(значение true) - рамка будет из символов + - |.

НЕСКОЛЬКО ЦЕЛЕЙ (CONFIG.bat -> 4). До 10 аккаунтов. У каждой цели своя
база DATA/history_<имя>.db и папка DATA/avatars/<имя>/. Первая цель из
версии 2.0 продолжает работать с history.db и DATA/avatars - история
не теряется. Можно задать метку (имя для уведомлений).

УВЕДОМЛЕНИЯ В TELEGRAM (CONFIG.bat -> 14).
  1) Создайте бота у @BotFather, скопируйте токен.
  2) CONFIG.bat -> 14 -> 1: вставьте токен.
  3) Нажмите /start у своего бота и в пункте 2 выберите "найти
     автоматически" (или добавьте chat_id вручную). Получателей
     может быть несколько: себе, другу, в группу.
  4) Пункт 3 включает уведомления, пункт 5 отправляет тест.
Присылаются: онлайн/офлайн, смена имени/username/описания, смена
аватарки (с фото: слева старая, справа новая). Фильтры - пункт 4.
Токен хранится в DATA/settings.json (секрет, не публикуйте).

ВЕБ-ПАНЕЛЬ (CONFIG.bat -> 15). Открывается на http://127.0.0.1:8765/
пока работает START.bat; доступна только на этом компьютере.
Вкладки: Обзор, Аналитика (время онлайн по дням, активность по часам,
тепловая карта день недели x час, статистика сессий), События,
Галерея аватарок. Обновляется каждые 10 секунд.

ГАЛЕРЕЯ АВАТАРОК. Для каждой смены показывается было -> стало с датой
и полный архив. Старая аватарка есть только если программа видела её
раньше: так работает Telegram. CONFIG.bat -> 17 сохраняет снимок
панели в DATA/exports/dashboard_*.html и открывает его в браузере
(работает и без запущенного мониторинга).

ТРЕЙ И ФОН (CONFIG.bat -> 16).
  - START.bat: окно с рамкой + значок в трее (пауза, веб-панель,
    скрыть/показать окно, обновления, выход).
  - START_BACKGROUND.bat: совсем без окна, остаётся только значок
    в трее. Сессия Telegram должна быть уже авторизована (один раз
    войдите через START.bat). Выход - через меню значка.
  - Автозапуск теперь в двух режимах: окно или фон.
  - В Windows Terminal (Windows 11) кнопка "Скрыть консоль" может
    не сработать - для этого и есть START_BACKGROUND.bat.
  - Нужны pystray и Pillow: устанавливаются автоматически.

ИМПОРТ И ЭКСПОРТ НАСТРОЕК (CONFIG.bat -> 18). Экспорт без секретов
(безопасно показать другому) или полный (api_hash, телефон, токен -
хранить как пароль). Импорт показывает список изменений, спрашивает
подтверждение и сохраняет копию прежних настроек в DATA/backups.
Сессия Telegram и история в файл настроек не входят.

ПРОВЕРКА ОБНОВЛЕНИЙ (CONFIG.bat -> 19). Программа ничего не
устанавливает сама, только сообщает о новой версии и даёт ссылку:
в рамке, в трее и в боте. Нужно один раз указать адрес источника:
репозиторий GitHub (https://github.com/владелец/репозиторий, берётся
последний релиз) или JSON-файл {"version": "2.2.0", "url": "..."}.
Пока адрес не задан, проверка отключена.

ОБНОВЛЕНИЕ С 2.0: распакуйте архив поверх старой папки. Папки DATA
и LOGS в архиве нет, поэтому настройки, сессия и история сохранятся.
settings.json будет автоматически приведён к новому формату, его
копия сохранится в DATA/backups.
